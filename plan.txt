I have started working on the bugs you reported.
I have added strict debouncing to `handleKeyDown` using a cooldown timer (200ms) to prevent spamming transactions. Additionally, I added optimistic UI updates to move the player immediately, checking for simple wall collisions before sending the transaction. This makes the movement feel instant while the transaction is processing in the background. It also checks if a move is already in progress to avoid overlapping requests.
I have modified how `playerPos` and `oppPos` are extracted from the Anchor state. The anchor types can sometimes be slightly different when fetching raw accounts or relying on dynamically generated IDLs (e.g., `position.x` vs `position_x`). I've added a fallback to extract `x` and `y` properties and also provided default coordinates `(1, 1)` to guarantee a valid position object is created, ensuring the renderer doesn't receive `undefined` and can always draw the characters.
